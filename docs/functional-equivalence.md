# 原小程序功能等价矩阵

本表把“原来可达的页面功能”“旧代码中只有包装器的兼容 API”和“本次新增 PC/营养师能力”分开，避免用接口骨架冒充完整迁移。

| 领域 | 原可达功能 | 新实现位置 | 验收要求 |
|---|---|---|---|
| 双角色认证 | 密码、短信、微信、注册、忘记密码、协议 | mini-program 共享页；API Auth | 三种登录链路、Token 过期、一次性验证码、医护注册码 |
| 患者首页 | 最新体重、BMI、目标、进度、通知、绑定提示 | 患者首页；`/dashboard` | 全部来自持久化数据，无静态目标 |
| 体重/饮食记录 | 体重历史；四餐、多食物、AI 热量、删除 | 患者记录页；`/health-records`、`/ai/calories` | 加餐不丢失；失败不显示假成功 |
| 健康报告 | 7/30/90 天体重/热量趋势、饮食日历 | 患者报告页；`/reports` | 使用真实目标体重和完整四餐 |
| 周/月总结与点评 | 医护按周期汇总记录并给出专业点评 | PC 患者详情、患者“医护总结”；`/clinical/patients/:id/care-summaries`、`/care-summaries` | 仅有效服务关系可发布；同医护同周期更新不重复；发布后站内通知直达总结页 |
| 医患绑定 | 扫码/输码、医生列表、解绑 | 双角色移动页；`/care/*` | 预览只读，确认后原子绑定，解绑后后端拒绝 |
| 患者随访 | 列表、筛选、各类型结果、图片、详情 | 患者随访页；`/follow-ups`、`/media` | ongoing 状态仍可提交；字段在双端一致 |
| 医生首页/看板 | 邀请码、患者/随访统计、趋势、预警 | 医生移动页与 PC；`/clinical/*` | 不使用静态百分比或按数组下标拼临床字段 |
| 医生患者管理 | 搜索、分类、详情、留言、解绑 | 医生移动页与 PC 患者视图 | 姓名/手机号搜索；详情路由真实存在 |
| 医生随访管理 | 单人/多人、六类、重复、自定义、状态 | 医生移动页与 PC 随访视图 | 重复记录带 series；状态机由后端强制 |
| 消息/通知 | 分页、已读、未读、删除、业务深链 | 共享消息页、通知页、PC；`/messages`、`/notifications` | 上下文持久化；通知 relatedId 指向可授权读取对象 |
| 兼容任务 API | 旧版有云函数但没有可达页面 | `/tasks`；PC 患者任务 | 作为兼容能力，不计入原页面数量 |
| 新增能力 | 营养师角色、PC 管理后台、OSS/本地私有媒体 | PC、RBAC、Media | 与医生共用关系边界，管理员无临床旁路 |

原版硬编码密钥、明文记住密码、无 JWT 的云函数、假邀请码、断路由、假指标和字段错配不是需要保留的行为，已按安全迁移规则替换。
